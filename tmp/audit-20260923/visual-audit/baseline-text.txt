Abstract



Digital education often relies on disparate platforms for communication,
contentdelivery,liveteaching,andassessment. Althoughthesetoolsmay
be individually effective, their separation creates fragmented workflows,
repeatedcontextswitching,andweakerinstitutionalcontinuity.Thisthesis
presentsEduVerse,anintegratededucationalwebplatformwithamobile
companion application, designed to consolidate these activities within a
governed,role-basedenvironmentforadministrators,teachers,andstudents.
   EduVerse provides a comprehensive suite of learning management
features,includingcontentdistribution,assessments,real-timecollaboration
via live sessions and whiteboards, an AI agent, and an integrated
browser-based IDE. The web platform is built using Next.js, React,
and TypeScript, integrating Supabase for authentication and relational
data, AWSS3forfilestorage, LiveKitforreal-timecommunication, and
OpenRouter for AI services.  EduVerse Mobile—developed with Expo
and ReactNative—extendsthe platform through selected high-frequency
workflows,  including class overviews,  chat,  notifications,  materials,
organizationswitching,andbasiclive-sessionparticipation.
   Theevaluationcombinesautomatedlogic-leveltestingwithengineering
verificationduringdevelopment. Theautomatedsuitecompletedwith76
passedtests,0failures,and105assertionsacross10testfiles,whileshared
APIreuseandmodularfeatureenablementsupportconsistentrole-based
academicworkflowsacrosstheimplementedclients.Consequently,EduVerse
contributesagoverned,extensiblemodelforreducingfragmentationindigital
learningenvironments.

5.2 DesignContextandArchitectural
         Structure

EduVerse is designed as a coordinated educational platform in which

organizational and class context.  The architecture separates the main
user-facingclientsfrompersistentdata,file-handlingservices,andreal-time

sessions.
   Thisstructureallowsindividualservicestoremaintechnicallydistinct
whilepresentinguserswithacoherenteducationalenvironmentgovernedby
sharedorganizational,role,class,andfeaturecontext.

PrincipalRelationshipStructure
   •Organization and membership structure.Organizations
      provide the institutional context for memberships, classes, settings,
      invitations, andconfigurablecapabilities. Usermembershiprecords
      connect individual accounts to the organizations in which they
      participate.

   •Role structure.Membership and role relationships allow access
      responsibilitiestoberepresentedwithinanorganizationcontextrather
      thanassigningonepermanentplatform-wideroletoeachuser.

   •Class participation structure.Classes belong to organizations,
      whileclass-membershiprelationshipsconnectuserstotheacademic
      workspacesinwhichtheyparticipate.Thisresolvesthemany-to-many
      relationshipbetweenusersandclasses.

   •Learning and communication structure.Materials and
      communication records are associated with classes so that learning
      resourcesandclassinteractionremaintiedtotheappropriateacademic
      context.

   •Assessment  structure.Classes  contain  assignments  and
      examinations, with related submission, question, attempt, and
      answerrecordsrepresentingthemainassessmentrelationships.

   •Configuration structure.Feature and extension settings relate
      platform capabilities to organization and class contexts, allowing
      supported tools to vary without changing the core academic data
      model.

Design SignificanceThe relational structure separates institutional
membership,classparticipation,academiccontent,assessment,andfeature
configuration while preserving the relationships required between them.
Intermediate membership and configuration entities are particularly
importantbecauseseveralEduVerserelationshipsdependoncontextrather
thansimpleownership.
   The ERD therefore provides the main design-level view of how
organizationalgovernanceandacademicactivityarerepresentedwithinthe
samedatamodel.
