# Eduverse Database Design Summary

The current Eduverse database follows a multi-organization educational platform model in which each organization acts as the top-level tenant and owns its members, role selections, feature settings, join workflows, classes, and class-level tools. Within this structure, class participation is modeled separately from organization membership so that organization roles, class rosters, teacher assignment, public join access, and archived past-term history can evolve independently. Learning content is persisted through class materials, chat-linked media records, assignments, assignment files, and assignment submissions, while formal assessment is handled through exams, exam questions, attempts, and answers, with released grades stored directly on submission and attempt records rather than in a separate results table. Communication is represented through class messages, notification records, public join requests, and live-session state, while AI support is implemented through feature flags and cached AI summary/extracted-content fields on materials instead of separate AI conversation tables. Extension support is stored through organization and class extension settings, whereas the built-in IDE is feature-gated in the database but its workspace state is not persisted in database tables. Historical/past-term tracking is implemented through archived classes plus imported assignment/submission grade records rather than a dedicated historical grades table.
