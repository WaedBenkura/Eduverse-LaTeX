\section{Introduction}\label{sec:testing_evaluation_introduction}

Testing and evaluation examine whether the implemented EduVerse platform
behaves according to its academic, role-based, and technical
responsibilities. In a multi-organization educational system, correctness is
not measured only by whether pages render successfully, but also by whether
access rules, workflow boundaries, and governed feature behavior operate
reliably in representative use.

The evaluation therefore concentrates on the main forms of verification adopted
in the current project scope: selected automated checks, manual validation of key
workflows, role-aware and security-aware review, and integration review through
pre-merge checks and preview deployments.

\section{Testing Strategy}\label{sec:testing_strategy}

EduVerse was evaluated through a layered strategy that combined several
complementary forms of verification:

\begin{itemize}
  \item selected automated logic-level tests for rule-heavy platform services;
  \item manual validation of representative academic and administrative
    workflows;
  \item role-based review of permissions, visibility, and feature gating;
  \item security-aware checking of protected routes, join flows, file access,
    and assessment controls;
  \item pre-merge review through GitHub Actions checks and Vercel preview
    deployments.
\end{itemize}

This approach suits EduVerse because several of its most important behaviors
depend on governed logic rather than on isolated interface rendering alone.
Results visibility, active-role resolution, feature availability, exam
integrity, and protected academic data all require validation at the level of
workflow and access control.

\section{Functional Validation}\label{sec:functional_validation}

Functional validation focused on representative workflows rather than on a
claim of exhaustive end-to-end automation. The main validation work covered the
following areas:

\begin{itemize}
  \item automated tests are present for selected logic-heavy components,
    including exam behavior, integrity-related rules, feature-registry
    resolution, IDE preview behavior, and class-access helpers;
  \item manual validation confirms protected authentication flow, organization
    creation, feature enablement, class configuration, material access,
    assignment handling, exam participation, results visibility, and live-session
    operation in the web platform;
  \item role-based validation confirms that Organization Administrator,
    Teacher, and Student views remain differentiated by access rights, class
    membership, and enabled features;
  \item security and access-control review confirms protected workspace entry,
    governed invite and public-join behavior, signed file access, and recorded
    exam integrity events;
  \item the mobile companion was validated more narrowly through authenticated
    access, organization switching, notifications, materials, class chat, and
    basic live-session participation.
\end{itemize}

\section{Non-Functional Evaluation}\label{sec:non_functional_evaluation}

The non-functional evaluation is necessarily lighter than the functional validation,
yet several practical conclusions remain well supported.

\begin{itemize}
  \item Maintainability is strengthened by the modular project structure, the
    shared API layer, and configuration-driven feature control.
  \item Usability was reviewed through representative workflow inspection and
    preview-based verification of role-sensitive pages and gated features.
  \item Compatibility and responsiveness were assessed at an observational
    level through the implemented interfaces, while formal load testing and a
    complete browser-automation matrix were outside the current testing scope.
\end{itemize}

\section{Review and Evaluation Summary}\label{sec:review_evaluation_summary}

Taken together, these testing activities provide a credible evaluation
foundation for EduVerse. Automated checks support selected core logic, manual validation
confirms representative academic workflows, and role-based and security-aware
review strengthens confidence in governed platform behavior. GitHub Actions
checks and Vercel preview deployments further support safe review before merge.

The evaluation was limited to selected automated checks, logic-level tests, and representative manual validation. Full end-to-end automation was outside the current testing scope. Accordingly, the evaluation supports conclusions about the correctness of core workflows, controlled access behavior, and the practical engineering discipline applied during implementation.
